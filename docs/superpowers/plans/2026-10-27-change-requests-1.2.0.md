# RFQ Insight 1.2.0 Change Requests Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver the twelve change requests of 23 Oct 2026 as plugin 1.2.0: AVL master deck, plain wording, English-only output, current skill areas, chat upload intake and Outlook e-mail input.

**Architecture:** The deterministic runtime under `plugins/rfq-insight/skills/rfq-insight/scripts/rfq/` is extended in place: the renderer opens a shipped AVL template instead of a blank deck, `validation.py` gains a language gate and a bracket-tolerant faithfulness check, `extractors.py` and `corpus.py` learn `.msg` with unpacked attachments, and a new `intake.py` copies chat attachments into the RFQ root. Prompts move to v15/v3 and the knowledge file is rewritten; SKILL.md gains the two permitted intake questions.

**Tech Stack:** Python 3.10+, python-pptx, pydantic, extract-msg (new), pytest. Tests live in `tests/` at the repo root with `conftest.py` putting the skill's `scripts/` on `sys.path`.

**Spec:** `docs/superpowers/specs/2026-10-27-change-requests-1.2.0-design.md`

## Global Constraints

- Plugin version `1.2.0` in `.claude-plugin/plugin.json`, `.codex-plugin/plugin.json`, `.github/plugin/plugin.json`, `asset.json`, `.claude-plugin/marketplace.json` (metadata and plugin entry).
- Every change works on Claude Code, Claude Desktop Cowork and Codex; SKILL.md stays provider-neutral (no harness tool names in the procedure body, `tests/test_invariants.py`).
- The plugin files under `plugins/rfq-insight/skills/rfq-insight/` use CRLF line endings for `.md`, `.py`, `.json` written from Windows; new files may be LF. Do not convert existing files.
- No real RFQ content, customer names or people's names enter the repository: the template asset carries no slides, the knowledge file carries no names, fixtures are generated by tests.
- Fonts: Verdana everywhere (the template's own), title 28 pt regular from the master.
- `Info not available` stays in table cells and Opportunity Info values; `not available` in prose.
- Deduction notes lines carry no rule code; codes stay in the run report and on the methodology slide.
- `PAGE_W, PAGE_H = 13.333, 7.5` must equal the template's slide size.
- Run `pytest tests -q` from the repo root with the toolbox venv (`python -m pip install -r requirements-dev.txt`); every task ends green. Commit after every task with a one-line subject.

## Review Focus
